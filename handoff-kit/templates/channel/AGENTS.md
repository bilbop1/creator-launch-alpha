# Channel agent instructions

This folder is one channel, `channels/<name>/` inside the orchestrator repo. Its success criteria are in `CRITERIA.md`; read it first and keep it current (DONE needs proof). Your plan for video 1 is `FIRST-VIDEO.md`, the evidence is in `research/`. The orchestrator (the repo root, two levels up) keeps `DECK.md`; send decisions that need the person there as cards.

House defaults: `handoff-kit/HOUSE-DEFAULTS.md` (at the repo root) is already decided and never asked. The goal is the biggest possible channel, multi-million-dollar scale. The channel is faceless unless the person handed over footage (listed in `FOOTAGE.md`), and the agents produce everything (script, AI voice, visuals, editing, packaging); the person never films, speaks or edits for you and is never asked to. They override a default only by saying so.

**Top priority: hill-climb against the competition before the person sees anything.** The parity spec is `research/parity/parity.json` (measured from their link: top performers against their own channel median, plus the watched style notes). How people make this kind of video with agents right now is `METHODS.md`; at the start of every session run `python tools/methods.py due METHODS.md --format <format>` and refresh it if due. Pick each pipeline stage from its proven techniques.

Isolation: use only this folder, the orchestrator repo and the web. Never read the user's other projects, threads, global memory or brain tools unless they ask. Never run account checks during onboarding.

Method: `handoff-kit/WORKFLOW.md` and `docs/FIELD-GUIDE.md` / `docs/RESEARCH.md` in this folder (at the repo root: `handoff-kit/`).

Build the channel yourself: proven references (outlier videos with real links and numbers), original concepts that pass the 3 second premise test, a script and shot plan, then the video. The person only makes taste calls, and approves an idea by name before any script, voice or animation. Never copy a format that is not proven by outliers. Never invent views, retention or earnings. Never publish, buy, sign in or message anyone without their explicit go-ahead for that action.

Before anything is locked, everything a competitor also makes (premise, script, title, thumbnail, hook, every shot type, motion, pacing, voice, music, captions, copy, the finished cut) wins a strict blind test against the best-performing competitor version (mock phone feed cards, pairwise, both orders, no story context, judges mostly from other model families, never the maker). Method: `handoff-kit/BLIND-TEST.md`; helper: `tools/feed_cards.py`. Each design climbs on its own loop (test, read the reasons, fix exactly that, retest, keep only if higher), all in parallel; never batch rounds or restart from scratch. Picture and sound are judged as real video with sound at phone size; climb each element while building it, never render blind and test at the end. A script wins blind at script level before anything is voiced or animated, and has a story spine; long-form runs 8:00 or more for mid-roll ads, one long-form at a time (Shorts may run in parallel). Every video passes `python tools/parity.py gate research/parity/parity.json --video <file> --title <title> ...` before review. All platform copy and the script voice pass `tools/copy_check.py` (Wikipedia "Signs of AI writing" patterns, `handoff-kit/SIGNS-OF-AI-WRITING.md`, zero dashes), then `tools/copy_check.py style` against `research/parity/competitor_titles.txt` or `competitor_descriptions.txt`, then a blind pairwise test against the most-viewed competitor's copy. Review finished media as the real video at full size with sound, never frame sheets, with clickable timestamps. Every review and morning report leads with the scoreboard (element, score, competitor tested against); anything that has not won says so. Thumbnail references are about 16 of the most-viewed similar competitor thumbnails (`research/parity/thumb-refs/`). Heavy work runs one job at a time, on the GPU path, at low priority, and never steals focus. Never say done without something the person can open. Post only on the person's word "post" for that exact video; never tick an AI-content label. After posting, run YouTube's Test and compare on the top 3 thumbnails and switch the title as soon as a better one wins. Ship first: the score is published videos and views. Before saying a helper is working, check it is alive that turn.
